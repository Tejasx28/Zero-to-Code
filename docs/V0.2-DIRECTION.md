# Revised direction — code is the main outcome

User decision, 9 November 2026: make DSA Quest code-oriented. Introduce Python and Java, teach concepts in simple words through interactions and flashcards, and help students learn to code independently while learning DSA. Begin with basics, arrays, and a few topics. Add 4–5 more substantial games/puzzles and expand only after testing.

This supersedes the earlier single-Stack lesson with a guided JavaScript selector. The beginner-first, discover-through-interaction, useful-mistakes, self-experiment, and independent-evidence principles remain.

## Implemented v0.2

- Coding-led dashboard, with Code studio as the main quest.
- Python and Java tracks; separate persistent drafts and results.
- Six focused chapters: language basics, conditions/loops, arrays, search, sorting, stacks.
- 22 concept cards with simple explanations and actual code examples.
- Seven regular code exercises plus an unassisted transfer task, in both languages.
- Free editing, actual browser-only Python/Java execution, varied tests, compiler/runtime feedback, cancellation, timeouts, source downloads, and help usage tracking.
- Five games with three different rounds each. Plans have constraints, multi-step outcomes, useful mistakes, restart, and revisit support.
- Saved game boards, code drafts, first submission scores, per-language passes, notes, and separately recorded pre/post/delayed concept checks.
- Original v0.1 record and vision documents preserved.

## The learning loop to test

Simple explanation → predict or plan → interact → inspect why it worked or failed → identify the repeating rule → write a general program → run different inputs → fix the bug → explain the code → solve a new task without a worked answer → return for delayed retrieval.

Games should be deeper without making confusing rules the obstacle. If the game is easy but the code is unreachable, improve the language and notation bridge. If game rules obscure the concept, revise the game. Playing skill is separate from programming ability.

## Next executable milestones

1. Choose one language first. Record where outside help becomes necessary. Close examples and ask whether you can write each solution independently.
2. Play all five games. Record route-planning confusion, shift-order mistakes, unjustified search elimination, incomplete sorting passes, and stack-planning errors.
3. Attempt sensor audit without a built-in hint or solution. Preserve the first score and revisions; a passing first submission and a later pass are different observations.
4. Return after 48 hours for the fresh concept check before reviewing. Also reimplement a regular exercise in a blank external file as a manual coding-retention task.
5. Revise the largest obstacle. Test with a new learner or new task, instead of treating memorized questions as unseen evidence.
6. Try a few other beginners with the same protocol. Only then add curriculum, adaptation, or backend services.

## Boundaries

No full curriculum, accounts/backend, AI tutor, leaderboard, or host-code execution. Browser runtimes load on demand. Free-form coding uses the exercise’s function signature. Output tests check behavior, not originality or algorithm complexity. The pre/post/delayed concept sets are comparable prototype questions, not a calibrated research instrument.
