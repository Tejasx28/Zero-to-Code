# Try v0.2 as its first learner

Choose one language first. Use the same browser and address for the experiment. Do not read the worked solutions, source question keys, or maintainer reference checks beforehand.

1. **Before learning:** take the optional baseline honestly and set your confidence. Skipping means there is no measured starting score.
2. **Language basics:** reveal each concept card only after making your own guess. Explain variable, function/method, input, return, and the language’s grouping rules in your own words.
3. **Write immediately:** open Code studio and try the supply calculator. Change the code yourself; run the tests. If it fails, read the expected versus actual return value. Printing a value and returning it are different.
4. **Connect each game to code:** program a Robot Relay route, preserve cargo in Memory Heist, justify a search elimination, complete sort passes, and plan top-only stack moves. After each, write the related general solution.
5. **Use help deliberately:** ask for a direction when stuck. Study a worked example only after an attempt; close it and reimplement the idea. Help usage remains recorded separately from whether the tests pass.
6. **Try unfamiliar inputs:** explain an empty input, duplicates, negatives, the last index, and a missing target before running them. Passing one example is not enough.
7. **Independent transfer:** write the sensor audit solution without outside help. No built-in hint or worked answer is available. Preserve your first submission result as well as subsequent revisions.
8. **Immediate snapshot:** after three regular code exercises pass, take the after-learning concept check without notes. Write which part of your code you can now explain without reading it.
9. **48–72 hours later:** return before reviewing explanations and take the fresh memory check. As an additional manual test, write one earlier function in a blank file without its starter or example.
10. **Improve one obstacle:** record whether confusion came from game rules, the DSA idea, syntax, indexing, tests, or moving from the picture to code. Revise that part before adding topics.

Export the diary before clearing data. Python and Java drafts/results stay separate. A correct output is useful evidence, but explain why the algorithm works and how much work it does. Later repeat the protocol with other beginners; your own improvement guides the design rather than proving it works for everyone.
