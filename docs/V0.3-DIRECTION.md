# v0.3 — a story that leads to independent code

The user asked for a much stronger interaction design: better writing and debugging spaces, hints that protect the learner’s thinking, a story-led theme instead of the classic left sidebar, and a Code Geass-inspired atmosphere using forest green, sand beige, and electric purple. The games must build DSA intuition that transfers into related coding tasks and questions.

## Product decisions

**The Cipher Rebellion** is an original tactical-anime learning campaign. The learner becomes a strategist who restores a city’s lost knowledge through code. Chess and command-academy imagery provide atmosphere; plain explanations, function contracts, and feedback remain understandable without following the fiction.

The central outcome is a general solution the learner can write and explain. More elaborate game controls do not, on their own, demonstrate learning.

1. Start with a prediction or a small plan. Notes remain optional; uncertainty is a valid starting point.
2. Let the learner manipulate the system and see the resulting state.
3. Make the discovered rule explicit without replacing it with a finished answer.
4. Arrange the algorithm’s steps and explain the rule in the learner’s own words.
5. Carry that reasoning into a freely editable Python or Java solution.
6. Debug using real evidence: inputs, returns, diagnostics, and actual Python traces.
7. Try a related problem that changes one useful assumption.
8. Measure unfamiliar application and delayed recall separately from activity.

## Games and code must teach the same rule

`src/learningLoops.ts` is the source of the game-to-code mapping. Robot Relay leads to a route interpreter; Memory Heist to safe row rotation; Signal Expedition to binary search; Sorting Workshop to repeated comparison-and-swap passes; Cargo Stackyard to reversal through LIFO access.

The bridge names what the learner kept track of, maps the visible actions to code concepts, asks a related question, and provides an algorithm-ordering practice activity. Related coding tasks make the next step concrete: for example, remove sorted order after binary search and ask which part of the strategy stops being valid.

## Interaction commitments

- Provide a real CodeMirror workspace with syntax, indentation, search, folding, undo, focus mode, and useful diagnostic markings.
- Let custom inputs test a learner’s theory without changing graded mission results.
- Use progressively more specific questions for hints. Record support honestly. Worked examples require an explicit learner choice; independent tasks have no built-in hints or worked answer.
- Offer actual Python line/local-variable replay, bounded to 180 recorded events per test. Keep Java’s capability explicit: real compiler diagnostics and test investigation, without claiming Java line tracing.
- Keep simulations reversible and inspectable through accessible program editing, step controls, Undo/Redo, and clear state feedback.
- Preserve saved v0.2 progress and the retained project vision. A visual redesign must not erase learning records.

## Scope and next milestone

The scoped slice remains six chapters, 22 cards, 12 regular exercises plus one independent coding task per language, and five games with 15 rounds. Backend services, accounts, AI tutoring, and a larger curriculum remain deferred.

The next test is whether the creator can move from a game’s rule to matching code without outside explanation. Record where that chain breaks: rules, concept, vocabulary, algorithm, syntax, debugging, related problem, or retention. Revise the largest obstacle before adding more content. Repeat later with other beginners and fresh tasks; do not treat memorized questions or repeated examples as independent evidence.
