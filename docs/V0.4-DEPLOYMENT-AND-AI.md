# v0.4 deployment and future AI

Checked against official documentation on **9 November 2026**. No site or model was published as part of this revision.

## What can run free now?

The current app is a static React/Vite frontend. Its C.C. guide uses written explanations and real test feedback; there is no model to train or host. Python and Java execute in the learner's browser through downloaded runtimes.

A static deployment is the simplest first pilot. Cloudflare Pages offers free, unlimited static-asset requests. Its Free plan currently allows 500 builds/month, 20,000 files per site, and 25 MiB per asset. Those limits fit a small static app, but should be checked against the final build before publishing. [Pages pricing](https://developers.cloudflare.com/pages/functions/pricing/), [Pages limits](https://developers.cloudflare.com/pages/platform/limits/)

Build with `npm run build` and serve the generated `dist` folder through a static host. Keep the browser runtime downloads reachable. Test actual Python and Java execution on the public origin before calling the deployment ready. Progress is local to that new origin, so the development browser's saved journey will not automatically appear there.

## Do I need to train a local LLM?

**No.** For this prototype, training would add cost and complexity before the learning experience has been validated. Curated C.C. guidance already supports the current curriculum.

Later, try an existing instruction model with trusted lesson excerpts, the active task contract, current code, and actual test/error evidence. This is a proposed extension, not an implemented feature. Start with a narrow hint-first assistant:

- Ask one useful question or suggest one diagnostic experiment.
- Ground explanations in the approved curriculum and selected runtime evidence.
- Treat learner source as input data, never instructions for the assistant.
- Keep full solutions behind an explicit supported-practice choice.
- Disable generated solution guidance during independent checks.
- Limit prompt size, output size, requests, and spending; retain authored hints when unavailable.

Compare generated hints with the curated version on real beginner mistakes before considering fine-tuning.

## Can downloaded model weights be deployed free?

**Sometimes a small demo can fit a free allowance. Downloading weights does not make public inference unlimited or free.** Compute, memory, model downloads, and service quotas still exist. Each model also has its own license and any access conditions. Read its model card and license before choosing it. [Hugging Face license documentation](https://huggingface.co/docs/hub/repositories-licenses)

| Option | Where the model runs | Practical meaning |
| --- | --- | --- |
| Ollama on your laptop | Your computer | Useful for private development. Its default server binds to `127.0.0.1:11434`; a public frontend does not automatically reach it. A visitor's localhost refers to that visitor's machine. Public service requires a deliberately exposed, available backend. |
| WebLLM | Each learner's browser/device | No central inference server is required, but each learner downloads/caches model artifacts and needs compatible WebGPU, device features, and enough memory. Keep this optional with a compatibility check and authored fallback. |
| Small hosted API | Provider infrastructure | Easier to use across student devices. Needs a backend route for credentials, usage caps, and a defined response when the allowance runs out. |

The Ollama conclusion follows from its documented default binding and deployment model. WebLLM documents browser execution and browser caching; its model configuration includes model-specific VRAM/device requirements. [Ollama FAQ](https://docs.ollama.com/faq), [WebLLM overview](https://webllm.mlc.ai/docs/), [WebLLM model/cache documentation](https://github.com/mlc-ai/web-llm/blob/main/README.md), [WebLLM device requirements](https://github.com/mlc-ai/web-llm/blob/main/src/config.ts)

## A reasonable next pilot

Keep static hosting and the curated guide first. If learner sessions show a need for adaptive help, add a small server-side API endpoint with a hard usage cap. Send only the relevant lesson, code, and test evidence.

Cloudflare Workers AI currently provides **10,000 Neurons/day** free, resetting at 00:00 UTC. On the Free plan, requests fail after the allocation is exhausted. More usage requires a paid plan; some models require billing even before that choice. This is a limited experiment allowance, not an unlimited free tutor. Pages Function requests also use Workers quotas. [Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/), [Pages Functions pricing](https://developers.cloudflare.com/pages/functions/pricing/)

For another provider such as Gemini, keep the API key in a backend proxy rather than a Vite/React client bundle. Google explicitly recommends this server-side approach for production clients. [Gemini API key guidance](https://ai.google.dev/gemini-api/docs/api-key)

Use one deployment path for the pilot, measure hint quality and usage, then decide whether more infrastructure is justified.

## Optional model-demo hosting note

Current Hugging Face rules differ from older tutorials: Static Spaces are free, but creating a Gradio/Docker Space on `cpu-basic` requires a PRO personal or Team/Enterprise organization subscription. Eligible verified personal accounts older than 30 days can host up to two free ZeroGPU Spaces. ZeroGPU is shared and queued; daily use is limited, currently 2 minutes anonymous or 5 minutes for a free signed-in account. It is a possible experiment venue, not an always-available production promise. [Manage Spaces](https://huggingface.co/docs/huggingface_hub/main/guides/manage-spaces), [ZeroGPU eligibility and quotas](https://huggingface.co/docs/hub/en/spaces-zerogpu)
