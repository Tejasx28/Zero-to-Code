# v0.5 — Useful guidance, then more independent code

The active plan builds on the retained original vision and the v0.4 coding-first revision. Scope stays functions, conditions, loops, and arrays. The creator remains the first learner testing whether the experience helps them think and write code without copying.

| Work package | Concrete outcome | Acceptance |
| --- | --- | --- |
| Contextual companion | Floating C.C. note opens one focused workroom | Opens/closes with keyboard; no auto-opening modal; reacts to actual events |
| Evidence tools | Actual inputs/results/errors, Python state replay, source jumps | No fabricated Java trace or invented runtime values |
| Own algorithm | Editable step board, pinning, comment scaffolding | Learner writes every step; no solution generated or prose score |
| Simple theory | Six focused references with four points and a thought/code map | Every concept leads to a related coding task; unknown words explained |
| More coding | Sixteen extra Python/Java problems | Varied behavioral cases; drafts and passes separate from story/mastery |
| Visual polish | Two contextual C.C. poses, responsive room/board, subtle motion | No forced scene backgrounds; reduced-motion support |
| Learning trial | Observe the creator solve a fresh problem after the guided flow | Record confusion, hint reliance, ability to explain, transfer, and delayed recall |

Next: run the self-test honestly. Change the part where a learner cannot form the next line of code. Add curriculum or AI only after those observations justify it. The current finite cases and authored feedback are prototype tools, not proof of learning or a general code tutor.
