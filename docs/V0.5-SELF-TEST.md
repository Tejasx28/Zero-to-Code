# v0.5 learner trial

Use your usual server address to keep progress. Export your Notebook before a fresh-start experiment. Do not use developer reference solutions during the learning trial.

1. Open Concepts → Loops. Read the four points, select each thought, and explain why the highlighted lines express it. Look up one unfamiliar keyword.
2. Keep your own rule in the Notebook. Follow the coding link and work from the starter.
3. Before writing syntax, open C.C. → Build my plan. Write steps in your own words, reorder if needed, pin them, then optionally add them as comments.
4. Write the implementation yourself. Run it, choose one failing case, and compare expected/actual values. For Python, replay the trace and find the first surprising state. Jump back to the editor and make one reasoned change.
5. Invent an empty, repeated, negative, or boundary input appropriate to the contract. Run it as an ungraded experiment. Request one nudge only if stuck, and record what you needed.
6. Pass the task, close the hints, and solve its related question from a fresh starter. Explain the change in your own words.
7. In Practice lab, try a different topic and one stretch problem. Search/filter, then reload and check that your source and plan remain. Switch language only if you want a separate attempt.
8. After the story array lessons, attempt the independent challenge without outside help. Record where you could reason alone and where you relied on an example.
9. Use the optional before/after code checks if still eligible. Return after 48 hours for the delayed check before reviewing. Also write a fresh program; a code-reading score alone is insufficient.

Record time spent coding versus reading, places you did not know what to do, hints used, whether the plan helped write a line, and whether the related problem could be solved independently. Do not treat repeated memorized questions as unseen mastery evidence.
