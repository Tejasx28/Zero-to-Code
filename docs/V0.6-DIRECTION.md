# v0.6 — Clear lessons and useful practice

The learning scope stays Python/Java functions, conditions, loops, and arrays. The creator remains the first learner testing whether the website helps them write code independently.

## Product decisions

- Main navigation: Learn, Concepts, Code studio, Practice, Debug lab.
- Notes remain saved and accessible from the footer and C.C.'s help. They are a supporting tool.
- Debug Lab contains four authored bugs. Repair uses existing broken source and real tests. A pass unlocks a separate starter with different tests and no solution hints. Drafts, hints, and results are separate by task, stage, and language. These practice passes do not award story passes.
- Lessons show one concept, four short points, and a three-step code map. Keywords, common mistakes, and personal notes are optional panels. The main next action is to try a related coding problem.
- C.C. uses short, factual messages. After a run she points to a real failing input and actual/expected result, or the reported error. She offers one hint at a time. The help room's extra experiments and planning prompts are collapsed until needed. No AI chat is implied or implemented.

## Navigation choice

Keep the React application and add real page URLs, standard links, browser history, and page titles. Current routes include `/learn`, `/learn/contract/game`, `/concepts/loops`, `/studio/sum-array`, `/practice/practice-first-positive`, `/debug/early-return/rebuild`, and `/notes`.

This is client-side routing, not a conversion to multiple independently rendered HTML documents. It provides shareable pages and Back/Forward without rebuilding the editor as separate apps. A future public marketing/docs site can use server-rendered pages if that becomes useful.

Assets and workers use a root base so nested URLs load correctly. Vite development/preview handle direct navigation. Production hosting must return index.html for unknown application paths. `public/_redirects` supplies the standard fallback for hosts that support that format; configure equivalent rewrites on other hosts. The current configuration assumes hosting at the domain root. Subfolder hosting needs explicit base and route handling.

References: [pushState](https://developer.mozilla.org/en-US/docs/Web/API/History/pushState), [popstate](https://developer.mozilla.org/en-US/docs/Web/API/Window/popstate_event).

## Next learning trial

Ask the creator to explain a loop, repair an unseen error, close the help, and write a fresh solution from a starter. Record where they get stuck and what help changes the next line they write. Repeat with a different task later. Test passes alone do not demonstrate learning or originality. Defer wider curriculum, backend, accounts, and AI until this trial identifies a need.
