# Try DSA Quest v0.7

Start the app with `npm run dev` in PROJECT1. Open the Local address printed in the terminal. Use the same address to retain your saved progress.

1. Open Code studio, select Python, and choose Charge every checkpoint. Type a function and press Enter: the new line uses four spaces. Tab or the indent buttons move selected lines; Show spaces reveals their indentation.
2. Remove the function body's indentation and run. Open C.C. → Fix code → Preview spacing fix. Review each changed line. Apply the preview, then run all tests. Ctrl+Z undoes the patch and Ctrl+Y redoes it on Windows. Compare the previous run with the new one below the editor.
3. Open Debug lab → A maximum that was never there. Run the original Python program. Open C.C. → Fix code → Find a smaller failing input. It should find a shorter negative input that still returns the wrong value. Run it in your workspace.
4. Try input lets you change the numbers yourself. C.C., deal me a test only fills a case; think through your return before running it. These experiments do not change your score.
5. Step through shows the real inputs, then the values changed by each executed line. Try Next, Back, and Play. Open this line in my editor keeps C.C. beside your draft on desktop.
6. Tap her portrait for a greeting. Failed tests trigger concern; passed full suites trigger a nod. Calm mode stops these motions. Your device's reduced-motion setting is respected too.
7. Close C.C. and write a related solution from a fresh starter. This is the useful learning check: can you turn the idea into code yourself?

The coach is authored, not AI chat. First Python/Java runtime downloads need internet. Python keeps up to 180 trace events. Java runs real tests but does not replay variables. The smaller-input search is bounded, and spacing previews require your review.

`npm run build` is safe and creates production files. To check those files, use `npm run preview`. The single HTML snapshot is only a visual preview; use the server for full code execution.
