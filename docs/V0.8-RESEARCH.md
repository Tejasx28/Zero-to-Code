# Research behind DSA Quest v0.8 — 10 November 2026

This is a design synthesis from primary studies and research projects. It does not establish that DSA Quest improves learning. The creator is still the first learner testing it.

| Source | Finding and limit | Decision in this build |
| --- | --- | --- |
| [Sentance, Waite & Kallia: PRIMM, 2019](https://eprints.gla.ac.uk/229013/) | 493 students across 13 schools; the PRIMM group did better on the post-test. Teacher mediation and classroom dialogue were central. A solo app cannot assume the same effect. | Play an observable rule, investigate a small program, change it, then make a related program from a fresh starter. The site supplies short explanations; it does not require a student-written explanation or assume classroom dialogue has been reproduced. |
| [Weinman, Fox & Hearst: Faded Parsons, CHI 2021](https://acelab.berkeley.edu/wp-content/papercite-data/pdf/parsons-chi2021.pdf) | Study with 237 students supported pattern learning; general code-writing transfer was comparable to direct code practice. Rearranging fixed fragments also restricts alternative solutions. | The main games accept freely written code. Optional starting frames supply setup and loop structure, leaving the decisions and updates to the student. Every world links to a changed contract with a fresh starter. |
| [Michaeli & Romeike: systematic debugging, 2019](https://computingeducation.de/pub/2019_Michaeli-Romeike_WIPSCE19.pdf) | Explicit debugging-process instruction improved debugging performance and self-efficacy in its classroom study. Practice alone and better error wording are not the whole intervention. | C.C. saves an actual observation, then compares changed code on the same input. A written hypothesis is optional thinking, never a required field. Cancelled runs never become evidence. |
| [Straubinger, Bloch & Fraser: Code Critters, 2024](https://arxiv.org/abs/2404.09246) | Mutation-game interactions connect choosing inputs with expected and actual behavior. The 40-child study supports engagement and enjoyment, not demonstrated independent Python/Java coding gains. | The counterexample arena runs actual buggy programs. Students choose both an input and its expected return. Success requires an observed mismatch, followed by a real code repair. |
| [Margulieux, Morrison & Decker: subgoal-labeled examples, 2020](https://link.springer.com/article/10.1186/s40594-020-00222-7) | Functional step labels helped near-term performance; later average exam performance was equivalent. | Each world gives four short labels that connect manual decisions to the code's state and updates. They support the task without replacing it. |
| [Ericson: adaptive Parsons problems, 2018](https://repository.gatech.edu/handle/1853/59890) | Completion puzzles were faster with similar pre/post gains in the reported studies. This does not prove independent mastery from puzzle completion. | Keep the earlier guided warm-ups as optional syntax support. Promote the new play/code/remix games; keep game clears separate from independently written solutions. |

## The concept-to-code gap

Knowing what an array is does not tell a beginner what to type. This build adds short animated cards and an action-to-construct guide: choose an intention, see the syntax, learn each token, insert one editable step, and use the compiler/tests as feedback. This is our design inference from the research, not an evaluated intervention. The guide gives constructs rather than a complete algorithm, and records assistance. The student chooses the decisions and writes the finished solution.

## What changes the mechanism

- A courier's manual route becomes a new test case. Its function must also handle different orders, blocked moves, edges, and unknown commands.
- Cargo decisions alter the capacity available for later crates. A rule, not an isolated arithmetic answer, determines the manifest.
- Mirror Vault has a swap budget. Temporary storage and paired indexes become visible through the player's actions.
- Signal Siege distinguishes the current chain from the best chain, including ties and interference.
- Counterexample Arena starts with a neutral input that all three buggy drones survive. Suggestions and random test deals are disabled here. Students must design the separating input themselves.
- The game's output replay follows returned values; it does not pretend to be a line-by-line execution trace. Python's separate variable tool uses actual recorded events. Java uses real compiler and return evidence.

## First learning trial

1. Before learning, save a code-reading check if desired. Skip it rather than taking it retrospectively.
2. Play a world and watch its short rule explanation.
3. Use a code-word card if the syntax blocks you. Write the function. Record constructs, frames, or spacing help used.
4. Use one deliberate experiment: input, actual observation, edit, same-input rerun.
5. Close help and solve the remix from its starter. Passing the original game does not count as this pass.
6. Try a different related problem later; retain the existing 48-hour code-reading follow-up too.

Record the first point of confusion, what helped the next line get written, the first score, assistance, and the fresh-task result. Use these observations to decide what to redesign next. Avoid speed penalties, rewards for opening hints, and claims that engagement proves learning.
